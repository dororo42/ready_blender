# 对比分析:Reaction_Diffusion_Generator_Pro v6 vs Ready→Blender

> 日期:2026-08-18 ｜ 对象:`Downloads\Reaction_Diffusion_Generator_Pro v6.py`(956 行,单文件插件,"Doro With AI")
> 背景:用户反馈该插件**预处理(remesh)后生成的纹理接近想要的效果**,要求分析根因并评估如何改进本项目
> 结论先行:**Pro v6 效果好的根因是四个叠加因素——顶点域求解、自动 Voxel Remesh、全局稀疏种子、Dirichlet 边界保持;而本项目当前是面域求解+中央种子+提示式 remesh+无边界处理,其中"面值→顶点面积加权平均"是明确的模糊环节。建议以"顶点域求解路径 + 一键预处理流程"为主体改造,全部可在现有五层架构内净室实现(借鉴数学思路,不复制代码)。**

## 1. Pro v6 插件概览

**架构**:单文件、无分层(计算/UI/pip 管理混排)、一次性执行(无播放/预览)、无测试。

**核心链路**(execute 一次完成):

```
选物体 → [可选]Voxel Remesh(按 target_faces 估算 voxel_size)
       → 检测边界顶点(边 link_faces ≤ 1)
       → 初始化 U=1/V=0,全局随机撒种 n_verts//20 个(V=1)
       → 顶点域 Gray-Scott 迭代 iterations 步(边邻接图拉普拉斯)
       → V 归一化 × displacement,沿顶点法线直接位移顶点
       → [可选]三角转四边
```

**性能方案**:numba njit(边循环标量内核) + pip 镜像管理 UI(清华/阿里/中科大等) + numpy np.add.at 回退。

**优点**:
- 一键出效果(单按钮全流程),零学习成本
- 预设直击纹理设计需求(珊瑚/斑点/迷宫/虫纹/科幻装甲/电路/机械 7 组)
- 边界 Dirichlet 处理让开放面纹理干净
- 折叠面板 UI 组织清晰

**缺点**(本项目的机会):
- 破坏性操作:remesh 直接改原对象(无副本)、位移直接改顶点坐标(仅靠 undo)
- 无实时预览(一次性 500 步,参数试错=反复全量重跑)
- 无画笔、无 2D 网格、无公式系统/CA/IO、无烘焙/导出
- numba 依赖需用户 pip 安装(extensions.blender.org 不允许捆绑 wheel,上架受限)
- 无撤销栈管理、无错误恢复;`np.random.choice` 未播种(结果不可复现)
- 单文件不可测试、不可扩展

## 2. 关键差异对比(效果根因)

| 维度 | Pro v6 | 本项目(当前) | 影响 |
|---|---|---|---|
| **求解域** | **顶点域**(U/V 长度=顶点数) | **面域**(data 长度=面数) | ★★★ |
| 邻接/拉普拉斯 | 边邻接,`sum(U[nbr]) − deg·U`(非归一化) | 面邻接(共享顶点),1/度归一化 | ★★ |
| **预处理** | **自动 Voxel Remesh**(bbox 面积÷目标面数开方×1.2) | 仅密度检测提示,用户手动 | ★★★ |
| **初始种子** | **全局稀疏**(5% 随机点,图案满铺) | 中央方形/圆盘扰动(局部生长) | ★★ |
| 边界处理 | Dirichlet(边界顶点 U=1/V=0 固定) | 无(边界失真) | ★ |
| 输出 | V 归一化→**直接位移顶点**(所见即所得) | 属性/GN(非破坏,但间接+默认模式陷阱 N8) | ★★ |
| 数值防护 | U,V 均 clamp [0,1] | a clamp [0,2], b [0,1] | — |
| 迭代方式 | 一次性阻塞 iterations 步 | timers 播放/烘焙/步进 | 本项目优 |
| 加速 | numba JIT(需安装) | fast_ops 预算子(1.9-2.5x,零依赖) | 各有优劣 |

### 2.1 为什么"预处理后纹理效果好"——四个根因

**R1 顶点域求解(最关键)**
顶点浓度直接=位移量,1:1 映射。本项目面域值要经 `_face_to_vertex_values` 面积加权平均映射到顶点——**三角化后每个顶点平均了 ~6 个面的值,等于一次低通滤波**,凹凸细节被抹平。这是效果差距的第一来源。

**R2 自动 Voxel Remesh**
RD 图案的均匀性由顶点分布均匀性决定。Voxel remesh 后顶点近似等距,图案尺度一致、不扭曲。本项目仅"建议 remesh"(面板提示),用户跳过则原始拓扑不均 → 斑图变形。用户特别提到"预处理后"效果好,正说明这一步是必要条件。

**R3 全局稀疏种子**
5% 均匀撒种 → 图案从全表面同时生长,满铺均匀。本项目中央扰动 → 图案从中心向外长,边缘空白,观感"局部"。

**R4 Dirichlet 边界**
开放面(平面/布料/衣袖)边界顶点邻居少,拉普拉斯不对称 → 边界处浓度失真、图案溃散。Pro v6 固定边界 U=1/V=0,边界干净。本项目无处理,开放面效果差。

另有两个次要因素:R5 V 场 min-max 归一化后乘位移(对比度拉满,凹凸明显);R6 纹理向预设参数(f/k 组合直接可用)。

## 3. 净室合规说明

借鉴内容均为**公开数学与通用工程实践**,无代码复制风险:
- 图拉普拉斯离散(`ΣU[nbr] − deg·U`)是图论标准算子,本项目 `core/ops.graph_laplacian` 已有同族实现
- Dirichlet 边界条件是 PDE 标准概念(Pearson 1993 亦讨论边界)
- voxel_size 估算公式为初等几何(bbox 面积/面数),可独立推导
- Gray-Scott 方程本项目已是净室实现

**红线**:不引用/翻译 Pro v6 源码文本;预设 f/k 数值为参数事实(非创作性表达),可采录但注明来源口径。

| # | 改造 | 方案 | 规模 |
|---|---|---|---|
| C1 | numba 可选后端 | backend 加 numba 尝试导入(缺则回退 numpy),官方上架不带依赖,高级用户自装提速 | ~80 行 |

### 不建议引入的 Pro v6 特性

- **pip 镜像管理 UI**(install/update/uninstall 算子):安全面窄(subprocess 执行 pip)、官方扩展平台审查风险,本项目不做依赖管理
- **直接修改原对象**:Pro v6 remesh 破坏原网格,本项目保持"副本非破坏"原则
- **无种子播种**:本项目已用固定 seed(42),可复现性是测试基线,保持

### 与现有架构的融合点

- A1 落在 core/field.py + core/rule.py + backend(五层不动,符合依赖方向)
- A2 复用现有 `RD_OT_mesh_triangulate_copy` 的副本模式 + `mesh_target_density` 属性(已在面板)
- A4 与 B2 的"边界保持"开关进 ReadySettings(面板②区块)
- 顶点域输出直接写 POINT 域属性/顶点位移,**绕过** `_face_to_vertex_values` 模糊环节
